## VERDICT: REVISE

The plan is strong where it matters most: it keeps the alpha's spine, names the four measured
failures correctly and traces every owner requirement to a module, a phase and a test. The backend
operation sets are enumerated per adapter, the measured negatives are kept out of the defaults, the
config surface refuses import-by-string, and the learning module is artifact-only. It is not yet
buildable as written. Phase 0/1 omit the work that the Phase 1 acceptance criteria depend on (the
five existing arms and the ingestion write path on the new contracts, plus the contract freeze is
ordered after the first adapter that uses it); one Phase 1 acceptance criterion contradicts the
plan's own no-lexical-parity position and cannot pass; the decision agent's fail policy has no
stated default and is not defined per agent type, which in Phase 1 (no guards yet) leaves the
fabricated-count path open; the typed scope depends on a metadata-schema contract that does not
exist in §3; the grounding section silently drops an existing fail-closed check; the classifier
agent reopens arbitrary code loading through config; today's reviewer/follow-up loop has no v2
home although the migration table maps to it; and one Phase 0 acceptance criterion relies on
cached raw replies that the notes say were never cached. Each is fixable without changing the
architecture.
