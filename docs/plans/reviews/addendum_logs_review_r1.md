# Review: V2 plan addendum A1 (log analytics, sources, pattern extractor), revision 1

Reviewed: `docs/plans/v2_addendum_logs_and_patterns.md` (rev 1, uncommitted) and its private
deployment companion (read only; nothing from it is reproduced here beyond generic, non-identifying
observations). Checked against: the owner's log-analytics requirements as relayed in the review
request, `docs/plans/v2_implementation_plan.md` (rev 3 + 2.0.0a2 amendment),
`docs/plans/reviews/a1_completeness_review.md` (Phase 2–4 scope, F-list and risks), `AGENTS.md`, and
the package source at `cccd8d2` (branch `v2/phase-0`). Every code claim below was checked with
grep/read. Date: 2026-11-04.

VERDICT: REVISE

The addendum is a strong, well-structured design: it keeps the immutable-generation and single
write-path principles, separates a read-only `sources/` contract from the storage adapters, makes
the LLM step propose-only with a deterministic gate and manual promotion by default, and sizes the
stores by signatures rather than lines. It is not yet buildable as written. Eleven findings would
cause a wrong build, an unsafe default or a missed hard requirement. (1) The read-only source contract contradicts itself
on cursor close. (2) Counts labelled `exact` are often token-match proxies. (3) The structured arm
cannot compute the advertised analytics: today it ranks groups by row count, buckets count rows, and
it refuses anything above 10 000 rows. (4) Retention with `keep_generations: 2` cannot pass its own
verifier. (5) `gc` runs in a cron process that cannot see the serving process's pins, and the
non-reentrant write lease conflicts with the run-daily design. (6) Ledger and other derived state
outlive retention. (7) The library identity enters the live index fingerprint, which breaks
existing indexes and serving after every approval. (8) The `$service` fact relations violate the
existing span-containment validator. (9) The library writer protocol contradicts its own
append-only rule. (10) The daily USD cap is unenforceable with a per-build in-memory meter. (11)
Redaction runs user regexes through Python `re` over attacker-influenced log text, under a config
surface the deployment uses but the package does not have. All of them can be fixed inside the
existing phase structure. Most need a contract paragraph and a test, not a redesign.
